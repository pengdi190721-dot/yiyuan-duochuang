# 数据复盘与本次发布建议（第 0 步）

用户第二次及以后来用时先做这一步：用上一次采集的数据（通常是前一天）复盘，告诉用户这次发什么、先发哪个平台、让摄影师拍哪些画面、预期有什么效果。结果写进内容数据中台的"诊断结论"和"本次发布建议"两部分。

## 步骤

1. **看数据新不新。** `setup_check.py --status` 的 `data_is_today` 为 false 时，问用户（单选）：更新数据（推荐）/ 用已有数据 / 跳过复盘直接出稿。
2. **更新数据。** 按 socai-workbench.md 的"每日复盘采集"拉自家账号近期作品，存进 `workbench/raw/`；视频号、携程请用户导出后放进 `workbench/手动导入/`（没有就跳过）。然后运行：

   ```bash
   python3 <技能目录>/scripts/collect_data.py
   ```

3. **读数据。** 读 `workbench/数据/作品明细.csv`、`账号.csv`、`meta.json`；如果有上一次的快照 `workbench/数据/历史/<上次日期>/作品明细.csv`，对比新增作品和点赞变化。需要时再读 `workbench/优秀案例.md`。
4. **写诊断结论。** 按 `templates/diagnosis.json` 写 `workbench/数据/诊断结论.json`，3–6 条。
5. **写发布建议。** 按 `templates/publish_advice.json` 写 `workbench/数据/发布建议.json`：一句话总建议、1–3 个选题、拍摄清单、这次不建议做的、数据缺口。
6. **生成数据中台。**

   ```bash
   python3 <技能目录>/scripts/dashboard.py
   ```

7. **讲给用户听。** 用 3–5 句话说结论和建议，告诉用户 `workbench/内容数据中台.html` 可以打开看完整版。然后问（单选）：按建议出稿 / 用我自己的素材出稿 / 只看数据，这次不出稿。

## 怎么从数据得出结论

- **先分组再比较。** 按内容类型给作品分组，例如人物、空间、餐饮、亲子设施、价格促销、节日活动、景观。分组依据是标题和正文的关键词；分不清的归"其他"。每组算条均点赞，和全号条均比。
- **同时看三个数。** 点赞看吸引力，收藏看实用性，评论看话题性。评论区里反复出现的问题，是下一次的选题。
- **样本要够。** 某组少于 5 条作品时，结论后面写"样本少，仅供参考"。
- **不编数字。** 所有数字都来自作品明细或 dashboard 的计算结果，写清是哪几条作品。
- **区分账号。** 不同账号的粉丝量不同，比较时优先在同一账号内部比。

## 拍摄建议怎么写

每个镜头写成拍摄清单的一行，交给摄影师就能直接拍：

| 字段 | 写什么 | 例子 |
| --- | --- | --- |
| priority | 高 / 中 / 低 | 高 |
| scene | 拍什么：主体、动作、场景 | 礼宾员给客人开车门的瞬间 |
| how | 怎么拍：横竖、比例、景别、时间和光线、人物状态、给文字留的位置 | 竖拍 3:4，半身，傍晚侧逆光，上方留三分之一空白，抓拍不摆拍 |
| use | 用在哪个平台的第几张 | 小红书封面、抖音图文首图 |
| expected | 预期效果，必须和数据挂钩 | 人物抓拍类封面近 30 天条均 21 赞，高于全号 10 |
| evidence | 依据：作品明细的具体作品，或优秀案例链接 | 作品明细第 1、3、7 条 |

拍摄通用要求（写进 how，按需选用）：

- 小红书、抖音、视频号、携程笔记用竖拍 3:4；公众号头条封面横拍，主体放画面中间，方便裁成 2.35:1。
- 用相机或手机的最高分辨率，不开美颜、不加滤镜，后期统一调色。
- 每个画面至少拍 3 张：远景、中景、特写各一张，给出图留选择。
- 要放大字的图，拍的时候就在画面上方或下方留出干净的区域。
- 有人物出镜的，提前确认本人同意，并保留授权。
- 真实场景抓拍优先，不摆拍过度；不拍别家酒店或景区的标识。

预期效果只能写"依据 + 方向"，例如"同类封面条均 21 赞，预期高于全号平均"，不能承诺具体数字或"一定爆"。

## 数据不够时

- 从未采集过数据，或自家作品少于 10 条：说明"数据不足"，建议改为参考优秀案例（见 case-research.md），并在 `data_gaps` 写清楚。
- 某个平台没有数据：这个平台的建议标"按经验给出"。
