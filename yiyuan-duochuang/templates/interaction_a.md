# 交互点 A：确认文案（在生图之前）

目的：用户确认文案和图片计划之后才调用 image2.6，避免为没确认的文案花生图额度。

## 做法

1. 一个平台问完再问下一个，顺序与第 ④ 步相同。
2. 每个平台先展示：
   - 3 个标题（或首图大字）备选，编号 A、B、C；
   - 正文或文案全文；
   - 图片计划：每张图一行，写"第 N 张：用哪张原图，图上写什么字"；
   - lint.py 的 WARN 项（如果有）。
3. 按下表依次提问。能用选项卡片就用卡片，不能就让用户回复编号。
4. 用户的回答写回 post.json，并原样追加到输出目录的 `交互记录.md`。

## 问题

| 问题 | 方式 | 选项 | 写回 post.json |
| --- | --- | --- | --- |
| 标题用哪个？ | 单选 | A / B / C / 我自己写（填写） | `chosen_title`（抖音、视频号是 `chosen_cover_text`） |
| 正文怎么处理？ | 单选 | 通过 / 按意见改（填写意见）/ 整篇重写 | 改完再跑一次 lint.py，再回到这一题 |
| 这些图要出哪几张？ | 多选 | 列出每张图，默认全选 | 没选中的图把 `selected` 改为 false |
| 原图不够，怎么办？（张数低于下限时才问） | 单选 | 我来补图（上传）/ 合并，减少张数 | 补图后更新内容卡和 `images` |

## 交互记录格式

```markdown
## 交互点 A · <平台名> · <时间>
- 标题：<用户选择>
- 正文：<通过 / 修改意见原文 / 重写>
- 图片：<保留的 slot 列表>
- 补图：<用户的选择>
```

全部平台确认后，告诉用户"开始生成图片"，进入第 ⑦ 步。
